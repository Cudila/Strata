Железо: RTX 5090, i7-14700KF, 128 ГБ RAM. Каждое плечо - своя загрузка сервера (порт 10078), все замеры плеча в одной загрузке,
плечи по очереди внутри `gpu-lock run claude-nemo-final`, llama-swap остановлен на время замеров.
Сырьё и скрипты: (рабочий каталог замеров, вне репозитория)

## Что слито
Ветка `strata-nemotron-conv` в `strata-nemotron-review` (после временных WIP-коммитов в обоих worktree).
Ветка `strata-nemotron-expert` не сливалась. Слияние оставлено НЕзакоммиченным (resolved, `git add` сделан, MERGE_HEAD на месте).

- batch-1 decode: SHARED_EARLY, LFU_FAST, MAMBA_SWAP, GPU_TOPK, MTP_EVENT (`docs/nemotron/BATCH1_RESULTS.md`).

## Конфликты и как разрешены
Конфликтовал только `src/program/nemo_main.cpp` (`run_serve`), 4 блока; `nemo_model.hpp/.cpp` и `CMakeLists.txt` слились автоматически.

1. Лямбда `feed`: взят цикл conv (чанки с чекпоинтами каждые `g_every` токенов), но вызов `m.forward(..., gtk_first ? nullptr : logits.data(), ...)` из batch-1
   (при GPU_TOPK и MTP логиты промпта на хост не читаются). Объявления `gtk_first` / `host_logits` стоят перед `feed`.
2. После `feed(prompt.size())`: если ничего не подавалось (`at == reused == prompt.size()`), то `host_logits = true`; `snapshot_logits()` читается только без кеша бесед
   (кеш бесед сам кладёт логиты чекпоинта в `logits` при restore/unpark). Условие `!cc_on` из conv сохранено.
3. Первый токен: ветка batch-1 (top-k с устройства через `topk_head` + `sample_topk`, иначе `sample` по хостовым логитам). `std::vector<int32_t> got` не дублируется - он объявлен выше (conv).
4. Окно спекции: ограничение `nd` по `max_new` и ветка «последний токен одним обычным шагом» из conv; `spec_step` вызывается с batch-1 аргументами
   `(pick, gk ? &pick_tk : nullptr, gk)`.
Сборки: `strata-nemotron` и `strata-vision` собрались без ошибок (одно старое предупреждение о неиспользуемой `lo` в `nemo_model.cpp:1935`).
Чекпоинты берут логиты с устройства (`head_out`), поэтому отказ от чтения логитов на хост при GPU_TOPK их не ломает.

## Ошибки и сбои
- Падений new и ошибок движка нет; бинарный поиск по ключам не понадобился.
- Первая попытка new-плеча не стартовала: мой `arms.sh` убивал не ту группу процессов (`server.pid` указывал на подоболочку), engine prod остался жить, ожидание
  «available >= 70 ГБ» истекло (34 ГБ), скрипт завершился, `llama-swap` на ~1-2 мин был запущен при ещё живом engine prod (без моделей, VRAM занята только engine).
  Engine убит вручную (`kill -TERM` группы), скрипт исправлен (`exec` + `$!`), плечо new повторено в отдельном `gpu-lock run`. OOM/rc=137 не было. Данные prod из первого прогона.
- Разные запуски: prod и new замерены в разных загрузках (по одной на плечо) с интервалом ~15 мин; кеш страниц и экспертов сопоставимы.
