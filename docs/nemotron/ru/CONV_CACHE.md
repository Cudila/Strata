# Чекпоинты и парковка диалогов (strata-nemotron)

Заметка реализатора. По умолчанию всё выключено: без флагов поведение прежнее (один VRAM-снимок на границе сообщения).

## Флаги движка (передаются через `args` конфига)
- `--prompt-cache N` — до N живых чекпоинтов (default 0 = выкл.). Пул из N буферов по ~165 МБ выделяется один раз при загрузке (pinned).
- `--prompt-cache-every M` — чекпоинт каждые M токенов длинного чтения (default 16384, 0 = выкл.; лучше кратно `--chunk`).
- `--conversation-cache-mib X` — бюджет pinned-памяти под запаркованные диалоги (default 0 = выкл.). Если X>0 и N<2, N поднимается до 2.
- Отладка: `STRATA_NEMO_DUMP_LOGITS=file` дописывает логиты после промпта каждого запроса; ключ запроса `nocache=1` (холодное чтение без кеша), `nocache=2` (прежний одиночный снимок).

## Устройство
- `NemoModel`: `ckpt_bytes`, `checkpoint_save/restore` (Mamba state+conv 40 блоков, `mtp.h`, pending/pending_pos/consumed_tok, pos, логиты головы), `kv_gen()` (растёт в `reset()`), `kv_cell_bytes`, `kv_save/kv_restore` (используемые ячейки [0,cells) каждого владельца K/V; при восстановлении кеш K/V дорастает).
- `ConversationCache` (`src/core/nemo_conv_cache.*`): живые слоты + арена для парковки (first-fit со слиянием). Парковка хранит глубочайший чекпоинт и до двух глубочайших границ сообщений, K/V общие [0, pos глубочайшего).
- Чекпоинты берутся: на границе сообщения; на границах чанков (абсолютная сетка кратна M); после генерации (Answer). Ids = промпт + реально поданные токены.
- Запрос: выбирается чекпоинт с самым длинным префиксом ids (живой или запаркованный), совпадают и ключи картинок (покрытые позицией; "?" не совпадает). Живой: H2D состояния, чекпоинты глубже отбрасываются (их K/V перезапишутся); перед этим, если есть парковка и отбрасывается более глубокий чекпоинт, он паркуется (ветвление/форк). Запаркованный: текущий диалог паркуется, `reset()`, H2D K/V и чекпоинта, запись удаляется. Нет совпадения: паркуется текущий, `reset()`.
- Вытеснение живых: LRU, кроме самого глубокого. Парковка: самый старый; запись, чьи ids — префикс новой, заменяется.
- При включённом кеше последнее окно спекуляции не подаёт токенов сверх `max_new`, иначе чекпоинт «после ответа» не совпадёт со следующим промптом.

## Проверка (один процесс, `--skip-w 0`, spec 5, чанк 16384, N=8, бюджет 3000 МиБ)
- Возобновление побитово совпадает с прежним снимком (разность логитов 0.0, те же токены) для живого и запаркованного случаев. От холодного чтения логиты отличаются на 2–4 (разбиение на чанки, а не кеш) — то же, что и сегодня при продолжении из снимка.
- Реюз: P(60K)→P+200: 60002; ответ: 20267 = промпт + 63 поданных токена; ветка P+A→P+B: 60002 (7.4 с → ~1.2 с); P(60K)→Q→P+100: 60002 после разпарковки.
- Парковка 60K: ~21–43 мс, 729–907 МиБ; разпарковка 60K ~17–18 мс, 22K ~10 мс; восстановление живого чекпоинта ~3.8 мс.
- Вытеснение: 8 диалогов по 22K при 3000 МиБ — без падений, самые старые (C1, C3) ушли (reused 0), оставшиеся (C5, C7, C8) реюзят 22002.

## Ограничения
- Парковка на каждой ветке: при обычном ходе без совпадения «ответа» (ответ перерисован иначе) каждый ход паркуется копия диалога; записи с несовпадающими префиксами копятся до вытеснения.
- Разпарковка не восстанавливает промежуточные чекпоинты (только до трёх при парковке).
- Совпадение с холодным чтением побитово — только при том же разбиении на чанки.
