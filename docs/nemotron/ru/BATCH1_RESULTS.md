# Пакет 1 (T1–T5): результаты реализации

Ветка `strata-nemotron-review`, не закоммичено. Все ключи по умолчанию выключены, поведение без ключей не менялось.
Замеры: RTX 5090, bench 32K контекста (`--ctx 32768 --gen 256 --spec 5 ...` из брифа), 40K токенов wikitext-2 test
(BPE по vocab/merges из `Strata-data/nemotron/tokenizer`; tokenizer.json там заглушка).

## Побитовая точность

Важная оговорка по методике: число слотов экспертов зависит от свободной VRAM в момент старта (152 или 156 слотов; на карте работали
чужие процессы), а от содержимого кэша зависят сами тексты (`--skip-w`). Сравнивать ids можно только при одинаковом числе слотов.

- T2: при 152 слотах ids совпали с OFF (md5 `abbd2e…`) в двух независимых запусках; `LFU_CHECK`: 1835 поисков жертвы, 0 расхождений.
- T3: при 152 слотах ids совпали с OFF (`abbd2e…`).
- T5: ids совпали с T2 и T3 в одной сессии (156 слотов, все три прогона), т.е. изменений нет; прямого OFF при 156 слотах нет.
- T1: ids МЕНЯЮТСЯ (ожидаемо, порядок fp-сложений): в первой партии при 152 слотах `f094e4…` против `abbd2e…`. ALL (с T1) совпал с T1 в 3 прогонах.
- T4 (`--temp 1.0`, seed 1): T4 отдельно против OFF при 152 слотах: ids совпали (`0d11b5f6…` в обоих). ALL --temp против OFF --temp различаются из-за T1, а не T4.
- Прогоны внутри одной загрузки (3 файла подряд) дают разные ids (кэш и LFU-счётчики «прогреваются»), это штатно и одинаково для OFF.

Из-за разных слотов и разного hit-rate (он решает больше, чем сами изменения) и шума от чужих процессов таблица НЕ даёт чистого
вывода «ключ быстрее/медленнее». Однопрогонные замеры первой партии при одинаковых 152 слотах: OFF 195.7 / 199.7, T2 197.6 / 198.1,
T3 204.1, T1 203.3, LFU_CHECK 191–194. То есть T3 и T1 дают порядка +2–4 % (в пределах разброса), T2 ≈ 0; ожидаемые 0.2–1 мс на окно
(1–5 %) укладываются в шум. Для чистого A/B нужен прогон с фиксированным `--expert-slots`.
Режим `--temp 1.0`: в первой партии при 152 слотах T4 отдельно 128.8 против 126.3 tok/s у OFF (+2 %); ожидаемого выигрыша 1–4 мс
на окно не видно, вероятно потому, что в bench `top_k=64` и узкое место в другом месте (требует профиля).

## Не сделано / проблемы

- `mamba_parity` и `moe_parity` собраны, но на GPU не запускались (lock был занят, по просьбе координатора замеры сокращены).
  mamba_parity вызывает прежние сигнатуры (новые аргументы по умолчанию nullptr).
- Первая партия замеров была частично испорчена: пока мой lock был «протухшим» (acquire привязан к pid оболочки), чужой прогон
  стартовал одновременно, два процесса по ~63 ГБ shmem вызвали OOM-kill (rc=137), и числа слотов менялись. Эти данные отброшены
  кроме перечисленных однопрогонных при 152 слотах. Далее использовался `gpu-lock run`.
- Первичное падение `allt_1`/`t3_1` с rc=137 — тот же OOM, не ошибка кода.
- Нет сборки HIP/SYCL: все изменения только в CUDA-библиотеке Nemotron.
